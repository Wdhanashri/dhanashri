## ① O-18 · Strategy

**Anchor:** *"`if type == ...` is a Strategy waiting to happen."*
**Yaad rakho:** *"Kaam wahi, tareeka alag."*

**This is the most common pattern in LLD interviews.** If you learn one, learn this.

### The trigger — memorise this

> Whenever you see `if type == ...` or `switch(kind)` **choosing between behaviours**, that is a Strategy.

```python
# 🚩
class Splitter:
    def split(self, kind, amount, users):
        if kind == "equal":   ...
        elif kind == "exact": ...
        elif kind == "percent": ...
```

```python
# ✅
class SplitStrategy(ABC):
    @abstractmethod
    def split(self, amount, users) -> dict: ...

class EqualSplit(SplitStrategy):   def split(self, amount, users): ...
class ExactSplit(SplitStrategy):   def split(self, amount, users): ...
class PercentSplit(SplitStrategy): def split(self, amount, users): ...

class ExpenseService:
    def __init__(self, strategy: SplitStrategy):
        self.strategy = strategy               # ← swap this, change everything
```

```
   ┌──────────────────┐        has-a       ┌──────────────────┐
   │  ExpenseService  │───────────────────→│ SplitStrategy ABC│
   └──────────────────┘                    └────────┬─────────┘
                                       ┌────────────┼────────────┐
                                       ▼            ▼            ▼
                                    Equal        Exact       Percent
```

### You already built this

L5, 🔨 3 — the swappable `splitter` on `Group`. **That was Strategy.** You met the mechanism before the name, which is the right order and the reason it should feel obvious rather than arbitrary.

### Where it shows up in real interview questions

| Problem | The Strategy |
|---|---|
| Parking Lot | pricing (hourly / daily / flat) |
| Splitwise | split type |
| Ride hailing | fare calculation (surge / normal) |
| E-commerce | discount rules, shipping cost |
| Vending machine | payment method |

**Every one of those is "same job, different method."** That's the phrase to listen for in the problem statement.

**Recall prompt:** *You see a five-branch if-chain choosing between behaviours. What pattern is missing?*

## ② O-19 · Factory

**Anchor:** *"One place that knows how to build things."*

Strategy is about *behaviour*. Factory is about **creation**.

```python
# 🚩 this if-chain spreads across your codebase
if split_type == "equal":     s = EqualSplit()
elif split_type == "exact":   s = ExactSplit(amounts)
elif split_type == "percent": s = PercentSplit(percents)
# ...and the same block appears in three other files
```

```python
# ✅ one place knows how to build
class SplitFactory:
    @staticmethod
    def create(split_type: SplitType, **kwargs) -> SplitStrategy:
        if split_type == SplitType.EQUAL:
            return EqualSplit()
        if split_type == SplitType.EXACT:
            return ExactSplit(kwargs["amounts"])
        if split_type == SplitType.PERCENT:
            return PercentSplit(kwargs["percents"])
        raise ValueError(f"unknown split type: {split_type}")
```

### The honest bit

**The if-chain didn't disappear — it moved.** And that's fine, because it now lives in exactly one place. Adding a type means editing one known file instead of hunting through four.

If you want it truly open/closed, use a registry:

```python
class SplitFactory:
    _registry: dict[SplitType, type] = {}

    @classmethod
    def register(cls, split_type, klass):
        cls._registry[split_type] = klass

    @classmethod
    def create(cls, split_type, **kwargs):
        return cls._registry[split_type](**kwargs)

SplitFactory.register(SplitType.EQUAL, EqualSplit)      # new types self-register
```

**Say the trade-off out loud in an interview.** *"A simple factory still has the if-chain, but in one place; a registry removes it at the cost of some indirection."* Knowing the trade-off beats knowing the pattern.

### Strategy vs Factory — the question you'll be asked

| | Strategy | Factory |
|---|---|---|
| About | **how** something is done | **which object** gets created |
| Question | "which algorithm?" | "which class?" |
| Lives | in the object using it | at the boundary, where input arrives |

**They pair constantly:** a Factory *creates* the Strategy. That's your Splitwise, exactly.

**Recall prompt:** *Strategy vs Factory — one sentence on the difference.*

## 🔨 Build it — 35 min · **Splitwise, final**

Create `lld/splitwise/final.py`. This is the deliverable — the thing you could walk through in an interview.

### 🔨 1 — assemble the whole design

```python
# Bring together everything:
#
#   Enums:      SplitType
#   Data:       User, Expense (dataclasses where sensible)
#   Strategy:   SplitStrategy ABC + Equal / Exact / Percent
#   Factory:    SplitFactory.create(split_type, **kwargs)
#   Core:       BalanceSheet   — the only thing that mutates balances
#               Group          — membership
#               ExpenseService — orchestrates, with injected dependencies
#
# Requirements it must satisfy:
#   1. add users, create a group, add members
#   2. add an expense with ANY split type — chosen by a string from "input"
#   3. show what each person owes each other person
#   4. settle_up(a, b) — clears the balance between two people
#   5. adding a new split type = one new class + one registration line
```

**Acceptance:** run a demo at the bottom of the file with 3 users and 3 expenses using 3 *different* split types, and print a correct balance sheet.

### 🔨 2 — the extension test

```python
# WITHOUT editing any existing class, add SharesSplit
#   (Dhanashri: 2 shares, Paritosh: 1 share, Riya: 1 share → 50%, 25%, 25%)
#
# One new class. One registration line. Nothing else.
```

**Acceptance:** it works, and you can point at exactly two additions. **If you had to edit something, the design isn't done** — fix the design, not the feature.

### 🔨 3 — the walkthrough

> Write a `DESIGN.md` next to it. Five short sections:
> **Classes** (one line each) · **Why Strategy** · **Why Factory** · **What I'd add next** · **What I deliberately left out and why**

That last section is the one that impresses. *"I didn't add an Observer because nothing needs notifying yet"* is a stronger answer than an Observer nobody asked for.
