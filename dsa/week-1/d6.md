## ① Warm-up · Pointers without sorting

Container With Most Water. Two walls, water between them.

```
       │           │
       │  ~ ~ ~ ~  │      area = width × min(left, right)
    │  │           │  │
 ───┴──┴───────────┴──┴───
    L                 R
```

Not sorted. Two pointers still work — but the *reason* changes:

```
1. Brute force:   every pair of walls.                  O(n²)
2. The waste:     most pairs can't possibly be better.
3. What kills it: start at the WIDEST pair, then only give up width
                  when you might gain height.
```

**The move: always move the shorter wall.**

Why? The shorter wall caps the height. Moving the *taller* one loses width and the height can't rise — strictly worse. Moving the shorter one at least gives you a chance.

```python
def max_area(h):
    l, r, best = 0, len(h) - 1, 0
    while l < r:
        best = max(best, (r - l) * min(h[l], h[r]))
        if h[l] < h[r]: l += 1          # move the shorter wall
        else:           r -= 1
    return best
```

**Say out loud:** *"Moving the taller wall can never help."* That sentence is the answer to the follow-up question.

## ② Concept C-07 · Max-from-both-sides

**Anchor:** *"Water height = min(tallest left, tallest right)."*
**Yaad rakho:** *"Paani utna hi rukega jitni chhoti deewar."*

Trapping Rain Water. This is the hardest problem in Week 1. It's also just C-05 + one idea.

**Start with one column, not the whole array.** How much water sits on top of *this* bar?

```
     █                 █
     █   ~ ~ ~ ~ ~ ~   █        water on bar i
     █   █         █   █          = min(maxLeft, maxRight) − height[i]
  ───┴───┴─────────┴───┴───
    maxL       i       maxR
```

Water is held by the **shorter** of the two tallest walls — pour more and it spills over that side. That one sentence is the whole problem.

Now: how do you know `maxLeft` and `maxRight` without scanning both directions every time? **Two pointers, tracking a running max on each side.**

```python
def trap(height):
    l, r = 0, len(height) - 1
    maxL, maxR = height[l], height[r]
    total = 0
    while l < r:
        if maxL < maxR:                 # left side is the binding constraint
            l += 1
            maxL = max(maxL, height[l])
            total += maxL - height[l]   # can't be negative — maxL includes height[l]
        else:
            r -= 1
            maxR = max(maxR, height[r])
            total += maxR - height[r]
    return total
```

**Why moving the smaller side is safe:** if `maxL < maxR`, then for the left pointer the answer is *already decided* — `maxL` is the smaller of the two, so whatever is further right can't change it. Settle it and move on.

**Gotcha:** water is bounded by the **smaller** max. Getting this backwards is the single most common bug here.
