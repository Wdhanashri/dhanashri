## ① Concept C-05 · Opposite-end pointers

**Anchor:** *"Sorted? Walk in from both ends."*
**Yaad rakho:** *"Sorted hai? Dono taraf se andar chalo."*

`[2, 7, 11, 15]`, target `18`. It's **sorted** — that's the whole gift.

```
[2, 7, 11, 15]
 L          R      2 + 15 = 17.  Too small.
                   Only L can raise the sum → L++

[2, 7, 11, 15]
    L       R      7 + 15 = 22.  Too big.
                   Only R can lower it → R--

[2, 7, 11, 15]
    L   R          7 + 11 = 18.  ✓
```

**Why this is allowed** — and you must be able to say this out loud:

> The sum is too small. `L` is already the smallest thing left. So `nums[L]` can't be in *any* valid pair with what remains — discard it and move on.

Each step deletes a whole row of possibilities. O(n) instead of O(n²).

```python
def two_sum_sorted(nums, target):
    l, r = 0, len(nums) - 1
    while l < r:
        s = nums[l] + nums[r]
        if s == target:  return [l + 1, r + 1]
        elif s < target: l += 1          # need bigger
        else:            r -= 1          # need smaller
    return []
```

**Gotcha:** on an **unsorted** array this is silently *wrong*, not slow. Always check sortedness before reaching for it.

## ② Concept C-06 · Skipping duplicates

**Anchor:** *"Same value as last? Slide past it."*

3Sum: find all triplets summing to zero, **no duplicate triplets**.

```
1. Brute force:   three nested loops.                O(n³)
2. The waste:     the inner two loops are just "find a pair summing to -x".
3. What kills it: ORDER (sort) → then TWO ENDS on the rest.   O(n²)
```

So: **fix one number, two-pointer the rest.**

```
sorted: [-4, -1, -1, 0, 1, 2]
          i    L           R      fix -4, find a pair summing to +4
```

Now the duplicate problem. `-1` appears twice — fix it twice and you emit the same triplet twice. **Skip duplicates in two places:**

```python
def three_sum(nums):
    nums.sort()
    out = []
    for i in range(len(nums)):
        if i > 0 and nums[i] == nums[i-1]:      # ① skip duplicate anchors
            continue
        l, r = i + 1, len(nums) - 1
        while l < r:
            s = nums[i] + nums[l] + nums[r]
            if s < 0:   l += 1
            elif s > 0: r -= 1
            else:
                out.append([nums[i], nums[l], nums[r]])
                l += 1
                while l < r and nums[l] == nums[l-1]:   # ② skip after recording
                    l += 1
    return out
```

**Gotcha:** skip ② must come **after** appending, never before. Skip first and you drop valid triplets.

**The transferable move:** *sorting doesn't just enable pointers — it puts duplicates next to each other, which makes them easy to skip.*
