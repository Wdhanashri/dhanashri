## ① C-40 · Minimum Spanning Tree

**Anchor:** *"Connect all n nodes with n−1 edges, as cheaply as possible."*

```
    A ──1── B          MST = the cheapest set of edges that
    │ ╲     │                touches every node with no cycle
    4   2   3                n nodes → exactly n−1 edges
    │     ╲ │
    C ──5── D          pick: A-B(1), A-D(2), B-D(3)?  no — cycle.
                       pick: A-B(1), A-D(2), A-C(4) = 7  ✓
```

### Prim — grow one tree outward. It's Dijkstra's shape.

```python
def min_cost_connect(points):
    n = len(points)
    adj = defaultdict(list)
    for i in range(n):
        x1, y1 = points[i]
        for j in range(i + 1, n):
            x2, y2 = points[j]
            d = abs(x1 - x2) + abs(y1 - y2)      # Manhattan distance
            adj[i].append((d, j))
            adj[j].append((d, i))

    total, visited = 0, set()
    h = [(0, 0)]                                  # (cost, node)
    while len(visited) < n:
        cost, node = heapq.heappop(h)
        if node in visited:
            continue
        visited.add(node)
        total += cost                             # ← add THIS edge's cost
        for nxt_cost, nxt in adj[node]:
            if nxt not in visited:
                heapq.heappush(h, (nxt_cost, nxt))
    return total
```

**Compare to Dijkstra — the difference is one line:**
```
DIJKSTRA   push (cost_so_far + weight, nxt)     accumulates along the path
PRIM       push (weight, nxt)                   only this edge's own cost
```
Dijkstra asks *"how far from the start?"*; Prim asks *"how cheap to attach this node at all?"*

**Kruskal — the other one.** Sort every edge, take it if `union` returns `True`, stop at n−1 edges. **That's Union-Find from D40.** You don't need to code it; know it exists and that it's DSU-based.

**The Gotcha:** in Prim you add the cost **when you pop**, not when you push — same rule as Dijkstra, same reason.

**Recall:** *Prim vs Dijkstra — what single thing differs in what you push?*

## ② Dijkstra with a constraint · Cheapest Flights Within K Stops

You want the cheapest route, but at most k stops. **Plain Dijkstra fails** — it might finalise a node via a cheap-but-long route and never consider an expensive short one.

**Use Bellman-Ford instead** — relax every edge, k+1 times:

```python
prices = [inf] * n
prices[src] = 0

for _ in range(k + 1):                 # at most k stops = k+1 edges
    tmp = prices[:]                    # ← snapshot, so one round can't cascade
    for u, v, cost in flights:
        if prices[u] != inf and prices[u] + cost < tmp[v]:
            tmp[v] = prices[u] + cost
    prices = tmp

return prices[dst] if prices[dst] != inf else -1
```

**The `tmp = prices[:]` copy is the whole problem.** Without it, a single round can chain several flights together and quietly exceed k stops.

**Say this if asked:** *"Bellman-Ford, because I need to bound the number of edges — and unlike Dijkstra it also handles negative weights."*
