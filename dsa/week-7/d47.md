## ① Three techniques

**Anchor:** *"Detect the cycle · handle the carry · halve the exponent."*

### Happy Number — a cycle in disguise

```
19 → 82 → 68 → 100 → 1 ✓ happy
 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 ↺  loops forever
```

**Two ways to detect the loop, and you already know both:**
```python
seen = set()                    # option A: the visited set (C-34)
while n != 1 and n not in seen:
    seen.add(n)
    n = sum(int(d)**2 for d in str(n))
return n == 1
```
Option B is **Floyd's fast & slow pointers (C-19, D19)** — `slow = f(slow)`, `fast = f(f(fast))`, O(1) space. Same algorithm as Linked List Cycle, on numbers instead of nodes.

**Say that out loud in an interview.** *"This is cycle detection — I can use a set, or Floyd's for constant space."*

### Plus One — the carry

```
[1,2,9] + 1

walk from the RIGHT:
   9 + 1 = 10 → write 0, carry 1
   2 + 1 = 3  → done
                        [1,3,0]

all nines: [9,9,9] → [1,0,0,0]   ← the array GROWS. That's the edge case.
```

### Pow(x, n) — fast exponentiation

```
x^10 = (x^5)²             halve the exponent, square the result
x^5  = x · (x^2)²         odd → peel one x off first

30 multiplications → 5
```

```python
def my_pow(x, n):
    def helper(x, n):
        if n == 0: return 1
        half = helper(x, n // 2)
        return half * half * (x if n % 2 else 1)
    return helper(x, n) if n >= 0 else 1 / helper(x, -n)
```

**The Gotcha:** compute `half` **once** and square it. Writing `helper(x, n//2) * helper(x, n//2)` recurses twice and you're back to O(n) — the code looks identical and the complexity isn't.

**Recall:** *Two ways to detect the Happy Number loop? Why does `half` have to be computed once?*
