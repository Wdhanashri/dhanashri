## ① C-39 · Dijkstra

**Anchor:** *"BFS with a heap instead of a queue."*

That's the whole difference. Genuinely.

```
BFS          deque       → always expands the NEAREST-IN-HOPS node
DIJKSTRA     heap        → always expands the CHEAPEST-SO-FAR node
```

**Why plain BFS breaks with weights:**
```
      A ──1──→ B ──1──→ C
      └────────5───────→┘

BFS reaches C in ONE hop (cost 5) and marks it done.
The 2-hop route costs 2 — cheaper — but BFS already committed.
```
BFS optimises hops. With weights you need to optimise **cost**, and a min-heap always hands you the cheapest frontier node.

### The code

```python
import heapq

def dijkstra(adj, start, n):
    dist = {}
    h = [(0, start)]                       # (cost_so_far, node)

    while h:
        cost, node = heapq.heappop(h)      # cheapest unfinished node
        if node in dist:
            continue                       # ← already finalised. Skip.
        dist[node] = cost
        for nxt, weight in adj[node]:
            if nxt not in dist:
                heapq.heappush(h, (cost + weight, nxt))

    return dist
```

**Compare it to BFS line by line** — `deque` → `heap`, `popleft` → `heappop`, and the tuple carries the cost. Everything else is identical.

**The `if node in dist: continue` line is the visited check.** A node can sit in the heap several times with different costs; the *first* time you pop it you have its cheapest route, so every later copy is stale and skipped.

**The Gotcha:** you finalise a node **when you pop it**, not when you push it. Marking on push locks in the first cost you happened to find, which is exactly the bug Dijkstra exists to avoid. And it **fails on negative weights** — worth saying out loud, since it's the standard follow-up.

**Recall:** *Dijkstra vs BFS — what's the one substitution, and when do you finalise a node?*

## ② Dijkstra in disguise · Swim in Rising Water

The "cost" isn't always a sum. Here it's a **maximum along the path**.

```
you can swim once the water level reaches the cell's height
→ a path's cost = the HIGHEST cell on it
→ you want the path whose highest cell is smallest

push (max(current_cost, grid[nr][nc]), nr, nc)     ← max, not +
```

**Same algorithm, one operator changed.** That's the transferable lesson: Dijkstra works for any cost that only ever grows along a path.
