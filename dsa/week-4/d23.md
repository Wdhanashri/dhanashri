## ① Concept C-21 · Info up vs info down

**Anchor:** *"Return value carries up. Parameter carries down."*
**Yaad rakho:** *"Sawaal upar se neeche jaata hai, jawab neeche se upar aata hai."*

```
                (5)         ← parameters travel DOWN
              ↙     ↘          bounds · depth · max-so-far · path-so-far
           (3)       (8)
          ↗   ↖
        return values travel UP
        height · count · sum · found?
```

**Ask this one question before writing any tree code:**

> *Does the child need to know something from above — or does the parent need something from below?*

```
needs info from ABOVE  →  add a PARAMETER
parent needs my answer →  use the RETURN VALUE
both                   →  do both
```

That's the entire concept. It takes ten seconds and it removes almost all structural confusion.

**Where it bites:** validating a BST. `left.val < node.val < right.val` checked locally is **wrong** — a node deep on the left must still be smaller than an ancestor far above it. That constraint comes from *above*, so it must be a parameter. You'll write this properly on D25.

## ② Return two things at once

Balanced Binary Tree — is every node's subtree height difference ≤ 1?

```
1. Naive:      for each node, compute both heights.        O(n²)
2. The waste:  height gets recomputed at every level.
3. What kills it: return height AND balanced-ness together, in one pass.   O(n)
```

```python
def is_balanced(root):
    def dfs(node):
        if not node: return (True, 0)              # (balanced?, height)
        lb, lh = dfs(node.left)
        rb, rh = dfs(node.right)
        balanced = lb and rb and abs(lh - rh) <= 1
        return (balanced, 1 + max(lh, rh))
    return dfs(root)[0]
```

**The transferable move:** *if you're computing the same thing twice, return a tuple instead.* This turns O(n²) into O(n) and shows up constantly in tree problems.

## ③ Two trees at once

Same Tree — the template, but walking two trees in step.

```python
def is_same_tree(p, q):
    if not p and not q: return True          # both empty → same
    if not p or not q:  return False         # one empty → different
    if p.val != q.val:  return False         # values differ
    return is_same_tree(p.left, q.left) and is_same_tree(p.right, q.right)
```

**Base cases first, always.** Three of them, in that order. Get them down before you write the recursive line.

Then Subtree of Another Tree **reuses** this function:

```python
def is_subtree(root, sub):
    if not sub:  return True
    if not root: return False
    if is_same_tree(root, sub): return True
    return is_subtree(root.left, sub) or is_subtree(root.right, sub)
```

Notice you're calling the function you wrote ten minutes ago. **That's how real code works** — and it's what interviewers want to see. Say "I'll reuse `isSameTree` as a helper" out loud.
