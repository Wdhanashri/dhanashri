## ① Concept C-20 · The tree recursion template

**Anchor:** *"Base case → recurse both sides → combine."*

```python
def solve(node):
    if not node:
        return <identity>          # 1. what's the answer for an empty tree?
    L = solve(node.left)           # 2. TRUST it. Don't trace it.
    R = solve(node.right)
    return <combine L, R, node.val>  # 3. what do I do with the two answers?
```

**Almost every tree problem is this shape.** Only `<identity>` and `<combine>` change:

| Problem | identity | combine |
|---|---|---|
| Maximum Depth | `0` | `1 + max(L, R)` |
| Same Tree | `True` | `L and R and vals equal` |
| Invert Tree | `None` | swap L and R |
| Count nodes | `0` | `1 + L + R` |

### The gotcha that matters most for you

**Do not trace the recursion three levels deep in your head.** That's what overloads working memory, and it's why recursion feels hard.

Instead: **assume `solve(node.left)` already returns the correct answer for that subtree.** Your only job is the combine step. One node. That's it.

```python
def max_depth(root):
    if not root: return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))
```

Read it as one sentence: *"my depth is 1 plus the deeper of my two children."* You never think about grandchildren.

**Say out loud:** *"I only write the rule for one node. Recursion handles the rest."*

## ② The one that isn't quite the template

Diameter — the longest path between any two nodes. It doesn't have to pass through the root.

```
        1              at node 1:  path through me = leftHeight + rightHeight
       / \                                          = 1 + 2 = 3
      2   3            but what my PARENT needs is my height = 1 + max(1,2) = 3
     / \
    4   5              ← two different numbers!
```

**You need to return one thing and record another.** Keep the answer in a variable outside the recursion:

```python
def diameter_of_binary_tree(root):
    best = 0

    def height(node):
        nonlocal best
        if not node: return 0
        L, R = height(node.left), height(node.right)
        best = max(best, L + R)      # ← the ANSWER, recorded
        return 1 + max(L, R)         # ← what the PARENT needs, returned
    height(root)
    return best
```

**Sit with the discomfort today.** This split gets a proper name and a proper explanation on D26 (C-24). Right now, just notice that *what you report* and *what you return* can differ.
