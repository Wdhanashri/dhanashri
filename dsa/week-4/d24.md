## ① Concept C-22 · BFS with deque

**Anchor:** *"One loop per level — snapshot `len(q)` first."*

DFS goes deep. BFS goes **wide** — one full level at a time.

```
        3            queue: [3]              level 0: [3]
       / \
      9  20          queue: [9, 20]          level 1: [9, 20]
        /  \
       15   7        queue: [15, 7]          level 2: [15, 7]
```

**The one line that makes it work:**

```python
from collections import deque

def level_order(root):
    if not root: return []
    out, q = [], deque([root])
    while q:
        level_size = len(q)              # ← SNAPSHOT before the inner loop
        level = []
        for _ in range(level_size):      # exactly this level's nodes
            node = q.popleft()
            level.append(node.val)
            if node.left:  q.append(node.left)
            if node.right: q.append(node.right)
        out.append(level)
    return out
```

**Why the snapshot.** You're appending children to the same queue while draining it. Without capturing `len(q)` *first*, the loop would run into the next level and you'd have no idea where one level ends.

**Gotcha:** `deque` with `popleft()`, **never** a list with `pop(0)`. A list's `pop(0)` is O(n) — it shifts every element — and turns your O(n) BFS into O(n²).

### When to pick which

```
DFS  →  "every node", height, sum, path, validity
BFS  →  "level", "shortest", "nearest", "minimum steps"
```

That table is worth more than either algorithm. In Week 7 it's how you'll pick between BFS and DFS on graphs.

## ② One-line variations

Right Side View — the last node of every level.

```python
def right_side_view(root):
    if not root: return []
    out, q = [], deque([root])
    while q:
        level_size = len(q)
        for i in range(level_size):
            node = q.popleft()
            if i == level_size - 1:          # ← the ONLY change
                out.append(node.val)
            if node.left:  q.append(node.left)
            if node.right: q.append(node.right)
    return out
```

**Notice what just happened.** Same skeleton, one changed line. Level averages, level maximums, zigzag order, node counts per level — all the same skeleton with one line different.

**The transferable move:** *learn the skeleton once, then vary one line.* Far cheaper for your memory than learning five "different" problems.
