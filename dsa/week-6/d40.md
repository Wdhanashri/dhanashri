## ① C-37 · Union-Find (Disjoint Set Union)

**Anchor:** *"Every group has one boss. Two nodes are together if they share a boss."*

```
   start: everyone is their own boss
   parent = [0, 1, 2, 3, 4]

   union(0,1) →  1's boss becomes 0        0 ← 1
   union(2,3) →  3's boss becomes 2        2 ← 3
   union(1,3) →  find(1)=0, find(3)=2      0 ← 1
                 → 2's boss becomes 0       ↑
                                            2 ← 3

   find(3) walks 3 → 2 → 0.  find(1) walks 1 → 0.  Same boss ⇒ connected.
```

### The whole structure — 15 lines

```python
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))       # everyone is their own boss
        self.rank = [1] * n                # tree size, for balancing

    def find(self, x):
        while x != self.parent[x]:
            self.parent[x] = self.parent[self.parent[x]]   # PATH COMPRESSION
            x = self.parent[x]
        return x

    def union(self, x, y):
        px, py = self.find(x), self.find(y)
        if px == py:
            return False                   # ← already together: this edge is redundant
        if self.rank[px] < self.rank[py]:
            px, py = py, px
        self.parent[py] = px               # attach smaller under bigger
        self.rank[px] += self.rank[py]
        return True                        # a real merge happened
```

**Two optimisations, both one line, both essential:**
```
PATH COMPRESSION   on the way up, point each node straight at its grandparent
UNION BY RANK      always hang the smaller tree under the bigger one
together → effectively O(1) per operation
```

**`union` returning a boolean is the trick that solves most problems:**
```
False  →  they were already connected  →  this edge creates a CYCLE
True   →  a genuine merge  →  components count drops by one
```

**The Gotcha:** you must call `find` on **both** nodes before comparing. Comparing `parent[x] == parent[y]` instead of `find(x) == find(y)` compares immediate bosses, not ultimate ones — and it's wrong in exactly the deep-tree cases DSU exists for.

**Recall:** *What does `union` returning `False` tell you?*

## ② The three problems this unlocks

| Problem | The DSU move |
|---|---|
| Number of Connected Components | start at `n`, decrement each time `union` returns `True` |
| Redundant Connection | the first edge where `union` returns `False` is the answer |
| Graph Valid Tree | a tree needs exactly `n-1` edges **and** no cycle |

**Graph Valid Tree in one line of reasoning:** *"n nodes, n−1 edges, no cycle → it's a tree."* Check the edge count first, then run every union and reject if any returns `False`.

**DFS also solves all three.** DSU is better when edges **arrive over time** — it answers after each one without redoing the walk.
