## ① C-36 · Topological sort

**Anchor:** *"Repeatedly take whatever has nothing left blocking it."*

Only for **directed acyclic graphs**. A cycle means no valid order exists — which is exactly why the same algorithm answers both questions.

### Kahn's algorithm (BFS) — the one to know

```
courses: 0←1, 0←2, 1←3, 2←3          in-degree = how many prerequisites left

   3 ──→ 1 ──→ 0                     indegree: {0:2, 1:1, 2:1, 3:0}
   └───→ 2 ──→ ┘
                                     queue = everything with indegree 0 → [3]
   take 3 → decrement 1 and 2 → both hit 0 → queue [1,2]
   take 1 → decrement 0 → 0 has 1 left
   take 2 → decrement 0 → 0 hits 0 → queue [0]
   take 0
                                     order: 3, 1, 2, 0  ✓ all 4 taken
```

```python
indegree = {i: 0 for i in range(n)}
adj = defaultdict(list)
for course, prereq in prerequisites:
    adj[prereq].append(course)
    indegree[course] += 1

q = deque([i for i in indegree if indegree[i] == 0])
order = []
while q:
    node = q.popleft()
    order.append(node)
    for nxt in adj[node]:
        indegree[nxt] -= 1
        if indegree[nxt] == 0:
            q.append(nxt)

return order if len(order) == n else []      # short → there was a cycle
```

**The last line answers both problems.** `len(order) == n` → no cycle, and `order` is the schedule. Course Schedule asks for the boolean; Course Schedule II asks for the list. **Same code.**

**The Gotcha:** the edge direction. `[course, prereq]` means **prereq → course** — you must finish the prerequisite first, so the arrow points *from* the prerequisite. Reversing this gives a valid-looking answer in the wrong order, and it is the single most common bug here.

**Recall:** *How does Kahn's algorithm detect a cycle?*

## ② Cycle detection with DFS — the three-colour idea

Worth knowing as an alternative, and it's the one asked about by name.

```
WHITE  not visited yet
GREY   currently on the recursion stack   ← hitting a GREY node = CYCLE
BLACK  fully explored, safe
```

**The key distinction:** in a *directed* graph, revisiting a **finished** node is fine (two paths reaching the same place). Revisiting a node **still on the stack** means you've looped back to where you came from.

```python
def has_cycle(node):
    if node in on_stack:  return True      # GREY → cycle
    if node in done:      return False     # BLACK → already proven safe
    on_stack.add(node)
    for nxt in adj[node]:
        if has_cycle(nxt): return True
    on_stack.remove(node)                  # ← leaving the stack
    done.add(node)
    return False
```

**The Gotcha:** `on_stack.remove(node)` on the way out. Forget it and every diamond shape looks like a cycle.
