## ① C-48 · Two inputs → a grid of subproblems

**Anchor:** *"Two things changing → `dp[i][j]`. The cache key is a pair."*

**Unique Paths.** Only right and down.

> `dp[i][j]` = **the number of paths from `(i,j)` to the bottom-right.**

```
    →  →  →  ┐
    ↓  ↓  ↓  │      to reach any cell you came from ABOVE or from the LEFT
    ↓  ↓  ↓  │      → paths(i,j) = paths(i+1,j) + paths(i,j+1)
    └──────► ★

    1  1  1  1       bottom row: only one way (keep going right)
    1  2  3  4       right column: only one way (keep going down)
    1  3  6  10      everything else: the sum of below and right
```

```python
@cache
def paths(i, j):
    if i == m - 1 or j == n - 1:  return 1      # last row or column: one way
    return paths(i + 1, j) + paths(i, j + 1)
```

**That's the same four steps.** The only difference is that the cache key is `(i, j)` instead of `i`.

### Spotting the second dimension

> **Ask: "what changes as I recurse?"** Two answers → 2-D.

| Problem | The two things |
|---|---|
| Unique Paths | row, column |
| Longest Common Subsequence | index in string 1, index in string 2 |
| Coin Change II | coin index, remaining amount |
| Target Sum | index, running total |

**The Gotcha:** the second dimension isn't always a second array. In Coin Change II it's *"which coins am I still allowed"* and in Target Sum it's *"what total have I built"*. **A "budget" or "remaining" is a dimension.**

**Recall:** *What question tells you a problem is 2-D rather than 1-D?*

## ② Counting ways vs finding the best

**Coin Change II** — how many *combinations* make the amount? (Not the fewest coins — the count.)

```
COIN CHANGE     dp[a] = FEWEST coins        → min(...) + 1
COIN CHANGE II  dp[a] = NUMBER of ways      → sum of the branches
```

**And the second dimension exists to stop double-counting.** Without a coin index, `1+2` and `2+1` count as two different answers:

```python
@cache
def ways(i, amount):
    if amount == 0:      return 1        # exactly one way to make zero
    if i >= len(coins) or amount < 0:  return 0

    return (ways(i, amount - coins[i])     # use coin i again (unbounded)
          + ways(i + 1, amount))           # move past coin i FOREVER
```

**The two branches are D33's `bt(i)` vs `bt(i+1)`** — reuse it, or retire it. Recognising that is the point: it's Combination Sum's structure with a cache bolted on.

**The Gotcha:** `amount == 0 → 1`, not 0. Making zero is **one** way (take nothing), and getting this base case wrong returns 0 for everything.

**Recall:** *Coin Change II — why does the state need a coin index at all?*
