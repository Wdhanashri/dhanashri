## ① DP on a grid — memoised DFS

**Longest Increasing Path in a Matrix.**

> `dfs(r, c)` = **the length of the longest increasing path STARTING at `(r,c)`.**

```python
@cache
def dfs(r, c, prev):
    if r < 0 or c < 0 or r >= rows or c >= cols or matrix[r][c] <= prev:
        return 0
    val = matrix[r][c]
    best = 1 + max(dfs(r+1, c, val), dfs(r-1, c, val),
                   dfs(r, c+1, val), dfs(r, c-1, val))
    return best

return max(dfs(r, c, -inf) for r in range(rows) for c in range(cols))
```

**Why no visited set?** Because the path must be **strictly increasing**, it can never return to a cell it left — the values would have to decrease. **The problem's constraint is the cycle protection.** That's a genuinely nice observation to make out loud, and it's the pretest answer.

**And that's why the cache works.** The answer from `(r,c)` never depends on how you arrived, only on the value you came from — so it's cacheable.

**The Gotcha:** Week 6 taught you that graph DFS needs `visited`. Here it doesn't, and the reason is specific to this problem. **Don't generalise either way** — check whether cycles are possible, every time.

## ② C-51 · Space optimisation

**Anchor:** *"If you only look back one row, keep one row."*

```
dp[i][j] depends only on dp[i-1][*]  and  dp[i][*]

    row i-1:   ■ ■ ■ ■ ■        ← the only history you need
    row i:     ■ ■ ■ ■ ■
    row i-2:   (never read again — free it)

    → keep TWO rows instead of m.   O(m·n) space → O(n)
```

```python
# full table
dp = [[0] * (n+1) for _ in range(m+1)]
for i ...:
    for j ...:
        dp[i][j] = f(dp[i-1][j], dp[i][j-1])

# two rows
prev = [0] * (n+1)
for i ...:
    cur = [0] * (n+1)
    for j ...:
        cur[j] = f(prev[j], cur[j-1])
    prev = cur                          # ← the whole optimisation
```

**When to mention it:** after your solution works. Say *"this is O(m·n) space, but since each row only depends on the previous one I can reduce it to O(n)."* **Don't write it first** — a rolling array is much harder to debug, and a correct slow answer beats a broken clever one.

**The Gotcha:** the same trick in 1-D collapses to **two variables** — which is exactly what you already did in House Robber (`prev1`, `prev2`) on D51. Same idea, one dimension down.
