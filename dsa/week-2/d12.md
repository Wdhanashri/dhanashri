## ① Concept C-12 · Monotonic stack

**Anchor:** *"Pop everything smaller — you just found their answer."*
**Yaad rakho:** *"Jo chhota hai, uska kaam ho gaya — pop kar do."*

Daily Temperatures: for each day, how many days until a warmer one?

```
1. Brute force:  for each day, scan forward for something bigger.   O(n²)
2. The waste:    days that are still "waiting" get rescanned constantly.
3. What kills it: keep the WAITING days in a stack. One arrival resolves many.
```

```
temps:  73  74  75  71  69  72  76
         │
      push 73 (waiting)              stack: [73]
      74 arrives → 74 > 73 → 73's answer is 1 day → POP
                                     stack: [74]
      75 arrives → 75 > 74 → POP     stack: [75]
      71, 69 → smaller → both wait   stack: [75, 71, 69]
      72 arrives → pops 69, pops 71  stack: [75, 72]
      76 arrives → pops everything   stack: [76]
```

The stack always holds **days still waiting**, in decreasing order. One warm day can resolve several at once.

```python
def daily_temperatures(temps):
    out = [0] * len(temps)
    stack = []                          # holds INDICES
    for i, t in enumerate(temps):
        while stack and t > temps[stack[-1]]:
            j = stack.pop()
            out[j] = i - j              # ← the distance, which is why we store indices
        stack.append(i)
    return out
```

**Why it's O(n) despite the `while`:** each index is pushed exactly once and popped at most once. 2n operations total. Say that out loud — it's the follow-up question.

**Gotcha:** store **indices**, not values. You almost always need the distance `i - j`, and you can always recover the value with `temps[i]`.

## ② Same tool, disguised · Car Fleet

Cars on a road, all heading to the same target. Faster cars stack up behind slower ones. How many fleets arrive?

**The reframe:** sort cars by position, **closest to the target first**. Then compute each car's solo arrival time.

```
target = 12
sorted by position (descending):  pos 10 (t=1)   pos 8 (t=4)   pos 5 (t=7)

pos 10 → time 1              stack: [1]
pos 8  → time 4 > 1  → it's slower, can't catch up → new fleet   stack: [1, 4]
pos 5  → time 7 > 4  → new fleet                                 stack: [1, 4, 7]

answer = len(stack) = 3
```

**The rule:** if my arrival time is **≤** the one ahead of me, I catch it — same fleet, so I don't push. Otherwise, new fleet.

```python
def car_fleet(target, position, speed):
    pairs = sorted(zip(position, speed), reverse=True)   # nearest the target first
    stack = []
    for p, s in pairs:
        stack.append((target - p) / s)                   # solo arrival time
        if len(stack) >= 2 and stack[-1] <= stack[-2]:
            stack.pop()                                  # absorbed into the fleet ahead
    return len(stack)
```

**The transferable move:** *when order matters, ask which direction to sort — the right one often makes the problem collapse.*

## ③ Same idea, both ends · Sliding Window Maximum

Filed under *Sliding Window*, but it's today's concept: a monotonic **deque**.

```
window slides →  need the max in each window

deque holds indices in DECREASING value order
  back:  pop while the new value is bigger (they can never be the max again)
  front: pop if it has slid out of the window
  → front is always the current max
```

```python
def max_sliding_window(nums, k):
    q, out = deque(), []
    for i, n in enumerate(nums):
        while q and nums[q[-1]] < n:  q.pop()        # back: smaller = useless
        q.append(i)
        if q[0] <= i - k:             q.popleft()    # front: expired
        if i >= k - 1:                out.append(nums[q[0]])
    return out
```

Same instinct as the stack — **anything a newcomer beats is dead, so remove it.**
