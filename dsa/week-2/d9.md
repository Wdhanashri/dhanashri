## ① Concept C-09 · The window invariant

**Anchor:** *"Name what makes a window valid before you code."*

Every window problem is the same three lines of machinery. The **only** thing that changes is one sentence: *when is this window still OK?*

| Problem | The window is valid while… |
|---|---|
| Longest Substring w/o Repeat | no character appears twice |
| Longest Repeating Char Replacement | `window_len − max_freq <= k` |
| Permutation in String | window counts == pattern counts |
| Minimum Window Substring | window covers every needed char |

**Write that sentence on paper, in English, before touching the keyboard.** Then:

```
grow R  →  while INVALID: shrink L  →  record answer
```

That's it. That's every window problem you will ever see.

## ② The one that teaches the invariant

Longest Repeating Character Replacement. You may change up to `k` characters. Longest run of one letter?

```
1. Brute force:  every substring, count its letters.        O(n²)
2. The waste:    windows overlap enormously.
3. What kills it: a window — but what makes it VALID?
```

**Think it through.** In a window, keep the most common letter and change the rest.

```
window "AABABBA",  k = 1

  window length      = 7
  most common letter = A, appearing 4 times
  letters to change  = 7 − 4 = 3
  is 3 <= k?  NO → invalid → shrink
```

**The invariant:** `window_len − max_freq <= k`. That's the sentence. Now the code is mechanical:

```python
def character_replacement(s, k):
    count = {}
    l = best = max_freq = 0
    for r in range(len(s)):
        count[s[r]] = count.get(s[r], 0) + 1
        max_freq = max(max_freq, count[s[r]])

        while (r - l + 1) - max_freq > k:      # ← the invariant, violated
            count[s[l]] -= 1
            l += 1

        best = max(best, r - l + 1)
    return best
```

**Gotcha — this one looks like a bug and isn't:** `max_freq` is never recomputed when the window shrinks, so it can be *stale*. That's fine. A stale `max_freq` only ever makes the window look worse than it is, and the answer can only be beaten by a genuinely larger `max_freq` later. Leave it.

## ③ Variant · The fixed-size window

Permutation in String — is any window of `s2` an anagram of `s1`?

Here the window **never shrinks**. It's a fixed size that slides:

```
s1 = "ab"  (length 2)

s2 = e i d b a o o o
     └─┘                counts don't match → slide
       └─┘              slide: remove 'e', add 'd'
           └─┘          "ba" → counts match ✓
```

**The move:** on each slide, remove the outgoing character and add the incoming one. Don't rebuild the count from scratch — that's the whole saving.
