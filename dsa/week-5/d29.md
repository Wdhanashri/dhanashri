## ① C-26 · `heapq` mechanics

**Anchor:** *"A heap gives you the smallest thing instantly — and nothing else."*

```
       [1]              a heap is a tree kept in a list
      ╱   ╲             parent ≤ both children (min-heap)
    [3]   [2]
   ╱  ╲                 heap[0] is ALWAYS the minimum   → O(1)
 [7]  [4]               push / pop                      → O(log n)
                        it is NOT sorted — heap[1] is not the 2nd smallest
```

```python
import heapq

h = []
heapq.heappush(h, 5)          # O(log n)
heapq.heappush(h, 1)
h[0]                          # 1 — peek, O(1), no removal
heapq.heappop(h)              # 1 — remove and return the smallest

heapq.heapify(nums)           # turn a list into a heap IN PLACE, O(n)
heapq.nlargest(3, nums)       # convenience, when k is small
```

**Python only has a min-heap. For a max-heap, push the negative:**
```python
heapq.heappush(h, -x)
biggest = -heapq.heappop(h)
```

**Tuples work, and compare left-to-right:**
```python
heapq.heappush(h, (dist, point))     # orders by dist, ties broken by point
```

**The Gotcha:** `heapify` is **O(n)**, not O(n log n) — building a heap from a list is cheaper than pushing n times. And if the tuple's second element isn't comparable (a dict, a custom object), a tie will crash. Add an index as a tiebreaker: `(dist, i, obj)`.

**Recall:** *How do you get a max-heap in Python, and what is `heap[0]`?*

## ② C-27 · The size-k heap

**Anchor:** *"To keep the k largest, hold a MIN-heap of size k and evict the smallest."*

This inverts your instinct, and that's exactly why it's worth learning properly.

```
find the 3 LARGEST of  [5, 1, 9, 3, 7, 8]

keep a MIN-heap of size 3:

push 5      [5]
push 1      [1, 5]
push 9      [1, 5, 9]
push 3      [1, 3, 5, 9] → size 4 → pop the min (1) → [3, 5, 9]
push 7      pop 3 → [5, 7, 9]
push 8      pop 5 → [7, 8, 9]

heap[0] = 7 = the 3rd largest.  Memory O(k), not O(n).
```

**Why a min-heap for the largest:** the heap's root is the *weakest survivor*. Anything smaller than it can't belong in the top k, so you evict from the root. Reverse it for "k smallest".

```python
def k_largest(nums, k):
    h = []
    for n in nums:
        heapq.heappush(h, n)
        if len(h) > k:
            heapq.heappop(h)        # drop the smallest survivor
    return h[0]                     # the kth largest
```

**Complexity:** O(n log k), and **O(k) memory** — this is the whole reason you'd use it over sorting. For a stream of a billion numbers, sorting isn't even possible.

**The Gotcha:** *"kth largest"* → **min**-heap of size k. *"kth smallest"* → **max**-heap of size k. Getting this backwards gives you the right-looking code and the wrong answer.

**Recall:** *k largest — min-heap or max-heap, and why that one?*
