## ① C-30 · The start index controls everything

**Anchor:** *"Pass `i` to reuse it. Pass `i+1` to move on."*

One character separates three different problems.

```
bt(i)      you may pick nums[i] AGAIN      →  unbounded  (Combination Sum)
bt(i + 1)  move past it forever            →  each used once (Subsets, Comb Sum II)
loop from 0, track used                    →  order matters (Permutations)
```

### Combination Sum — reuse allowed

```python
def combination_sum(nums, target):
    res, path = [], []
    def bt(i, total):
        if total == target:
            res.append(path[:]); return
        if total > target or i >= len(nums):
            return                            # prune: dead branch

        path.append(nums[i])
        bt(i, total + nums[i])                # ← same i: reuse this number
        path.pop()

        bt(i + 1, total)                      # ← move on, never use it again
    bt(0, 0)
    return res
```

**Read the two recursive calls as the two decisions:** *"use this coin again"* and *"I'm done with this coin forever."* That's the whole problem.

```
target 7, nums [2,3]
   take 2 → 2 → take 2 → 4 → take 2 → 6 → take 2 → 8 ✗ prune
                                        └ skip → +3 → 7 ✓
```

**The Gotcha:** the `total > target` check isn't an optimisation — without it you recurse forever on positive numbers. **Pruning is part of correctness here, not a nicety.**

**Recall:** *`bt(i)` vs `bt(i+1)` — what does each one mean?*

## ② Duplicates in the input — the sort-then-skip move

**Anchor:** *"Sort first, then skip a value you've already tried at this level."*

`[1, 2, 2]` — subsets. Naively you get `[1,2]` twice, from the two different 2s.

```python
nums.sort()                                   # duplicates now adjacent

def bt(i):
    res.append(path[:])
    for j in range(i, len(nums)):
        if j > i and nums[j] == nums[j-1]:
            continue                          # ← already tried this VALUE here
        path.append(nums[j])
        bt(j + 1)
        path.pop()
```

```
sorted: [1, 2, 2]
level 0:  try 1 · try 2 · (skip the second 2 — same value, same level)
                    │
level 1:            try 2   ← allowed! it's a DEEPER level, not a repeat
```

**The condition is `j > i`, not `j > 0`.** You're skipping repeats *at this level*, not everywhere — the second 2 is legitimately used one level down.

**The Gotcha:** this is exactly the two-level duplicate skip from **3Sum (C-06, D5)**. Same idea, different container. If it feels familiar, it should.

**Recall:** *Why is the duplicate check `j > i` and not `j > 0`?*
