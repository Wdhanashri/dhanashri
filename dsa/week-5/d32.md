## ① C-29 · The backtracking template

**Anchor:** *"Choose → explore → un-choose."*

You met this on D11 in Generate Parentheses. Today it gets its name and its shape.

```
                    [ ]
            ┌────────┼────────┐
        take 1              skip 1
          │                   │
        [1]                  [ ]
      ┌──┴──┐             ┌──┴──┐
   take2  skip2        take2  skip2
    [1,2]  [1]         [2]     [ ]
     ...

every leaf is one answer · every edge is a CHOICE you must undo on the way back
```

### The template — memorise this shape

```python
def solve(nums):
    res, path = [], []

    def backtrack(i):
        if i == len(nums):              # 1. base case: a complete answer
            res.append(path[:])         #    COPY — path keeps mutating
            return

        path.append(nums[i])            # 2. CHOOSE
        backtrack(i + 1)                # 3. EXPLORE
        path.pop()                      # 4. UN-CHOOSE   ← the line people forget

        backtrack(i + 1)                #    the "skip it" branch

    backtrack(0)
    return res
```

**Two lines carry everything:**

```
path[:]     you MUST copy. Appending `path` itself stores a reference to a
            list that keeps changing — every answer ends up identical (and empty).

path.pop()  without it, choices leak into sibling branches. This is THE
            backtracking bug, and it produces answers that look almost right.
```

**The Gotcha:** the recursion tree has 2ⁿ leaves for subsets, n! for permutations. **That's expected** — these problems have exponentially many answers, so exponential time is the *correct* complexity, not a failure. Say that out loud; candidates often apologise for it.

**Recall:** *The three words of the template, and the two lines that always break?*

## ② Two shapes, one template

**Subsets** — each element is take-or-skip:
```python
def subsets(nums):
    res, path = [], []
    def bt(i):
        if i == len(nums):
            res.append(path[:]); return
        path.append(nums[i]); bt(i+1); path.pop()    # take
        bt(i+1)                                       # skip
    bt(0); return res
```

**Permutations** — every unused element is a candidate at every position:
```python
def permute(nums):
    res = []
    def bt(path, remaining):
        if not remaining:
            res.append(path[:]); return
        for i in range(len(remaining)):
            bt(path + [remaining[i]], remaining[:i] + remaining[i+1:])
    bt([], nums); return res
```

```
SUBSETS       decide take/skip for each element   → 2ⁿ
PERMUTATIONS  pick any unused element next        → n!
```

**The difference in one line:** subsets ask *"do I include this?"*, permutations ask *"which one goes next?"*

**Recall:** *Subsets vs permutations — what question does each one ask at every step?*
