## ① C-42 · Memoise the recursion

**Anchor:** *"Same recursion. Add a cache. That's DP."*

**Climbing Stairs.** To reach step `n`, you arrived from `n-1` or `n-2`. So:

```python
def climb(n):
    if n <= 2: return n
    return climb(n-1) + climb(n-2)
```

**That's correct — and it's O(2ⁿ).** Here's why:

```
                climb(5)
              ╱          ╲
        climb(4)          climb(3)
        ╱     ╲            ╱    ╲
   climb(3)  climb(2)  climb(2) climb(1)
    ╱   ╲                 ▲
climb(2) climb(1)         └── climb(3) computed TWICE
   ▲                          climb(2) computed THREE times
   └── and again
```

The tree recomputes the same thing over and over. **The fix is one line:**

```python
from functools import cache

@cache                          # ← that's it. That's dynamic programming.
def climb(n):
    if n <= 2: return n
    return climb(n-1) + climb(n-2)
```

**O(2ⁿ) → O(n).** Each `n` is computed once, then served from the dictionary.

### The three questions that make any DP

```
1. What's the BASE CASE?        the smallest input you can answer directly
2. What's the RECURRENCE?       how does n depend on smaller inputs?
3. What's the STATE?            what arguments identify a subproblem?
```

**The state is what you cache on.** For Climbing Stairs the state is just `n` — one number, so a 1-D cache. Later this week the state stays one number; next week it becomes two.

**The Gotcha:** `@cache` only works when the function's arguments **fully determine** the answer. If your function also reads a mutable outside variable, the cache will happily serve you a stale answer. Everything the answer depends on must be an argument.

**Recall:** *What is the difference between a plain recursion and DP?*

## ② C-43 · The same thing, bottom-up

**Anchor:** *"Top-down asks. Bottom-up builds."*

```
TOP-DOWN (memoised recursion)      BOTTOM-UP (table)
start at n, recurse down           start at the base, build up

@cache                             dp = [0] * (n+1)
def f(n):                          dp[1], dp[2] = 1, 2
    if n <= 2: return n            for i in range(3, n+1):
    return f(n-1) + f(n-2)             dp[i] = dp[i-1] + dp[i-2]
                                   return dp[n]
```

| | Top-down | Bottom-up |
|---|---|---|
| Write it | **easier** — it's just the recursion | needs you to know the order |
| Speed | slight call overhead | slightly faster |
| Risk | recursion depth limit (1000 in Python) | none |
| Space | can be trimmed | can be trimmed to O(1) |

**And once you have a table, you often only need the last two values:**
```python
a, b = 1, 2
for _ in range(3, n+1):
    a, b = b, a + b            # O(1) space
return b
```

**Say the progression out loud in an interview:** *"Brute force is exponential; I'll memoise it for O(n); and since I only look back two steps I can do it in O(1) space."* That sentence, unprompted, is worth a lot.

**The Gotcha:** **write top-down first, every time.** Bottom-up requires knowing the fill order before you understand the problem, which is backwards. The conversion is mechanical once the recursion exists.

**Recall:** *Which do you write first, and why?*
