## ① Concept C-17 · Pointer surgery

**Anchor:** *"prev, curr, nxt — save next before you cut."*

Reverse a linked list. The trap: the moment you re-point `curr.next`, **the rest of the list is gone** — you've lost your only way to reach it.

```
prev    curr    nxt
None  →  [1] →  [2] → [3] → None

① nxt = curr.next      SAVE FIRST — this is your lifeline
② curr.next = prev     cut, and point backwards
③ prev = curr          shuffle forward
④ curr = nxt

after one round:
        prev   curr
None ← [1]     [2] → [3] → None
```

```python
def reverse_list(head):
    prev, curr = None, head
    while curr:
        nxt = curr.next        # ①
        curr.next = prev       # ②
        prev = curr            # ③
        curr = nxt             # ④
    return prev                # ← prev, not head. head is now the TAIL.
```

**Those four lines, in that order.** Don't derive them under interview pressure — write them from muscle memory.

**Gotcha:** `return prev`, not `head`. After reversal, `head` points at the last node.

## ② Concept C-18 · Dummy node

**Anchor:** *"A fake head means no special case for the real one."*
**Yaad rakho:** *"Nakli head lagao — asli ka tension khatam."*

Every list operation has an annoying question: *what if it's the first node?* A dummy node deletes that question.

```
without dummy:        [1] → [2] → [3]        removing [1] needs special code

with dummy:    [•] → [1] → [2] → [3]         [1] now has a predecessor
                ↑                             like everything else.
              fake head                        No special case exists.
```

```python
dummy = ListNode(0)
dummy.next = head
# ... do the work, always via dummy ...
return dummy.next            # NEVER `return head` — head may have been removed
```

**Use it whenever the first node might be deleted, moved, or merged.** Merge Two Sorted Lists:

```python
def merge(l1, l2):
    dummy = ListNode(0)
    tail = dummy
    while l1 and l2:
        if l1.val <= l2.val:
            tail.next, l1 = l1, l1.next
        else:
            tail.next, l2 = l2, l2.next
        tail = tail.next
    tail.next = l1 or l2          # attach the whole remainder — don't loop it out
    return dummy.next
```

**Gotcha:** always `return dummy.next`. Returning `head` is *the* classic bug when the original head got removed.

## ③ Three things you already know, stacked

Reorder List: `1→2→3→4→5` becomes `1→5→2→4→3`.

```
1. Find the middle          ← fast & slow pointers (tomorrow's concept, preview)
2. Reverse the second half  ← C-17, exactly as written above
3. Interleave the two       ← alternate, one node at a time
```

**Nothing new.** This is how hard linked-list problems actually work: three easy steps in sequence. When a list problem looks impossible, ask *"what three simple operations would get me there?"*
